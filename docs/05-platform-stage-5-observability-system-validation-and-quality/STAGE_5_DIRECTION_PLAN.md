# Platform Stage 5 三部分方向计划

状态：顶层方向已于 2026-07-27 通过人工 Gate；不替代各 Slice Spec/ADR

## 总体目标

Stage 5 用可信运行数据和可重复系统测试定位并修复学习主链路的不稳定性，使
Course Reader、Tutor 和 Practice 达到可持续迭代的质量基线：

```text
最小观测事实
  -> 代表性系统测试与 CI Gate
  -> 基于证据的质量和交互优化
  -> 回归、真实 smoke 与阶段总结
```

三个部分存在依赖，但不要求完全串行。最小观测合同建立后，核心系统测试应尽快
落地；后续观测、测试和优化可以按小 Slice 交替推进。

## 第一部分：可观测与成本

目标：让维护者能够回答一次 Tutor、Practice 或 Tool 运行发生了什么、为何
失败、消耗多少，并能关联到安全的业务对象和 eval 结果。

候选范围：

- 盘点并统一 Agent Run、Tool Call、Job、eval、usage、latency 和错误分类。
- 为 Tutor、练习生成、评分、代码执行和科学工具建立可比较但不抹平差异的运行
  摘要。
- 定义 provider/model、人民币单价快照、成本事件和价格版本候选合同。
- 建立失败率、成功率、重试、延迟、token 和人民币成本视图。
- 定义保留、聚合、脱敏和高基数边界。

优先顺序：

1. 先做事实盘点和最小安全数据合同。
2. 再做查询/API 和离线报告。
3. 最后决定是否需要完整 dashboard；页面不是第一交付物。

明确不做：

- 将完整 prompt、回答、用户答案、Memory 或 Tool 原始输入输出写入通用 trace。
- 用估算金额冒充 provider 实际 usage。
- 建设多币种、实时汇率、折扣、套餐或精确账单系统。
- 在没有人民币单价版本和归因规则时伪造金额；此时保留 usage 并标记成本未知。
- 借观测改写业务事实来源。

候选完成 Gate：

- 指标能够回读到真实 Run/Tool/Job/eval。
- 失败分类、usage、延迟和重试口径可由固定案例重复验证。
- 敏感正文和内部配置不会进入公开 API、日志或成本事件。

## 第二部分：CI 与系统测试

目标：建立能代表真实用户主流程、能够发现跨层回归的验证体系。

候选范围：

- 建立一条最小纵向系统路径，覆盖 Web、API、worker、Postgres 和必要 adapter。
- 为 Course/Tutor、普通练习、编程练习分别建立小而稳定的系统案例。
- 固定 Python/Java/C++ compiler/runtime 环境，关键 matrix 不允许静默 skip。
- 分层定义 unit、component、orchestration、database、environment、browser 和
  real-provider eval。
- 对概率性功能维护固定小样本、成功率、失败分类、延迟和成本基线。
- 在 CI 中区分快速必过 Gate、受控系统 Gate 和显式付费/远程 Gate。

明确不做：

- 要求普通 PR 默认调用真实付费 provider、Judge0 或 Wolfram。
- 用 mock 全绿替代 compiler、worker、数据库或浏览器环境 Gate。
- 把所有历史测试一次性重写为大型端到端套件。

候选完成 Gate：

- 核心纵向路径可在干净环境重复运行，失败能定位到稳定类别。
- 关键测试破坏对应产品行为时会失败。
- CI 明确显示跳过、环境阻塞和外部 Gate，不把它们计作通过。
- 系统测试失败能够关联第一部分的安全 trace 和指标。

## 第三部分：最终优化

目标：根据观测和系统测试证据，收敛 Stage 4 遗留的质量与交互问题，不横向
增加新 capability。

当前候选方向：

- Tutor 回答的检索相关性、结构稳定性、引用、代码解释、工具使用和诚实降级。
- 普通练习与科学题的生成、验证、有限 repair、评分和错误投影。
- Python/Java/C++ 编程题的生成成功率、可编译执行率、canonical contract、
  reference validation、确定性评分和反馈。
- Course Reader/课节界面的文本排版、代码块、公式、引用、长内容阅读、状态和
  响应式交互。

拆分原则：

- 本部分现在只保留问题域，不提前锁定 Slice 数量或实现方案。
- 每个优化 Slice 必须绑定可复现失败、当前基线、目标指标和回归路径。
- 后端质量、编程工具链和课节交互默认是不同风险轴，不合并成一个大 Slice。
- 改变公开行为、schema、评分权威、预算或队列状态时，重新进入对应 Spec/ADR
  Gate。

候选完成 Gate：

- 优化前后使用同一固定案例和指标比较。
- 自动化、环境 Gate、真实 provider eval 和浏览器 smoke 的结果分别记录。
- 没有针对固定输入、关键词或预期答案的专用修复。
- 课节与 Tutor/Practice 交互经过桌面和移动视口的真实浏览器验收。

## Stage 5 强制执行规则

1. 一个 Slice 默认只承担一个主要风险轴。
2. Spec 接受后，先建立最小真实编排或纵向验收路径，再扩大实现。
3. 第一条纵向路径可运行后立即做小范围 smoke，不等 Slice 收尾。
4. 测试结果分层报告，不再只汇报合并后的 passed 总数。
5. 关键测试加入反事实检查；源码字符串检查不能作为主行为证据。
6. 概率性功能使用固定小样本和分布基线，不以单次成功验收。
7. 编译器、容器和远程能力先经过 environment preflight。
8. 同一实现连续约两轮 correction 仍未收敛时暂停，重新拆包或补事实。
9. 交互状态和失败反馈进入完成 Gate，不作为后期装饰。
10. 完成声明区分已自动验证、已真实 smoke、离线模拟、环境阻塞和未验证。

## 暂缓边界

备份恢复与部署安全加固顺延到后续阶段。若 Stage 5 为 CI 建立 test image、
Compose profile 或本地代理，只能声明测试基础设施完成，不能据此宣称生产部署
已经安全加固。
